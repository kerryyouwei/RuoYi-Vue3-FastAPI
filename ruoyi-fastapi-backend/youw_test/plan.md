# 股票策略列表与回测页面

## Summary

- 在现有 `stock` 模块下新增“策略管理”页面，用于发现 `youw_test/strategies/` 中的策略、查看源码和运行回测。
- 参考图片实现“策略列表 → 参数配置 → 回测运行 → 收益概览/曲线/成交明细/日志”的闭环。
- 图片仅作为视觉参考，不把截图中的文字、按钮或平台行为当作额外业务指令。
- 保留现有 `stockDay` 页面及其已完成的导入功能。

## Backend Changes

- 新增策略控制器，例如 `module_stock/controller/stock_strategy_controller.py`，统一前缀 `/stock/strategy`：
  - `GET /list`：扫描策略目录，返回名称、分类、描述、文件修改时间、历史运行次数、最近运行状态、最近收益率等。
  - `GET /{strategy_name}`：返回策略元数据、只读源码、策略参数定义和可运行参数。
  - `POST /run`：创建回测记录并立即返回 `runId`，参数包括策略名、股票代码、起止日期、初始资金、手续费率、可选基准代码和策略参数。
  - `GET /run/{run_id}`：返回后台运行状态、进度、错误信息及完成后的摘要。
  - `GET /run/{run_id}/detail`：返回完整指标、策略/基准/超额收益曲线、回撤曲线、成交记录和运行日志。
  - `GET /{strategy_name}/history`：返回该策略的历史回测记录，支持分页。
- 新增策略 VO、DO、DAO/Service：
  - 策略元数据从 `.py` 文件名、模块 docstring、文件修改时间和可选模块常量中推导。
  - 分类默认固定为 `code`，策略可通过 `CATEGORY` 常量覆盖。
  - 名称默认由模块名格式化展示，可通过 `DISPLAY_NAME` 覆盖。
  - 使用数据库表持久化每次回测的参数、状态、指标、曲线、成交明细和日志 JSON。
  - 运行状态采用 `pending/running/success/failed`；后台任务完成后更新数据库。
  - 使用进程内后台任务执行回测，并在服务启动时将遗留的 `running` 记录标记为失败，避免页面永久等待。
- 将 `test_BaseStrategy.py` 中的数据加载和 Backtrader 流程抽成可复用的策略运行服务：
  - 继续使用 `load_stock_data` 和 `load_strategy` 的现有逻辑。
  - 接入 `TimeReturn`、`DrawDown`、`SharpeRatio`、`TradeAnalyzer` 等分析器。
  - 扩展基础策略运行期记录订单成交、交易盈亏、账户资金和日志。
  - 生成策略净值曲线；填写基准代码时额外生成基准收益和超额收益曲线。
  - 基准代码为空时不计算基准相关指标；填写后默认按相同日期范围加载基准行情。
  - 对策略名、参数名、代码和日期范围做白名单/格式校验，禁止任意模块路径导入。
- 增加股票策略数据表初始化 SQL，兼容 MySQL 与 PostgreSQL；模型导入后仍由现有 `Base.metadata.create_all` 机制支持开发环境自动建表。
- 在菜单初始化 SQL 中增加股票目录、策略管理菜单及查询/运行/详情权限，页面路径为 `stock/strategy/index`。

## Frontend Changes

- 新增 `src/views/stock/strategy/index.vue`：
  - 顶部查询区：策略名称、分类、运行状态。
  - 策略列表字段：名称、分类、描述、修改时间、历史回测次数、最近运行时间、最近收益率、最近状态。
  - 行操作：查看详情、运行策略、查看历史。
  - 详情/运行抽屉或对话框：
    - 左侧展示只读 Python 源码。
    - 右侧配置股票代码、日期范围、初始资金、手续费率、可选基准代码和策略参数。
    - 运行按钮提交后显示运行 ID 和状态。
  - 运行结果区域：
    - 收益概览卡片：策略收益、年化收益、基准收益、超额收益、夏普比率、最大回撤、胜率、盈亏比、交易次数。
    - ECharts 曲线：策略净值、基准净值、超额收益、回撤。
    - Tabs：成交明细、运行日志、历史运行记录。
    - 状态异常时展示后端错误信息，并允许重新运行。
- 新增 `src/api/system/strategy.js`，封装上述策略列表、详情、运行、状态、结果和历史接口。
- 复用现有 Element Plus、分页、抽屉、表格、标签和 ECharts 风格，不引入新的 UI 框架。
- 通过动态路由菜单加载页面；必要时补充前端页面路径映射，确保 `stock/strategy/index` 可以正常解析。

## Test Plan

- 后端：
  - 策略扫描只发现合法 `.py` 策略模块。
  - 默认分类为 `code`，自定义名称/分类/描述可正确覆盖。
  - 非法策略名、非法参数、日期倒置和不存在策略返回校验错误。
  - 使用 mock 行情验证回测状态流转、收益曲线、指标、成交明细和日志落库。
  - 验证后台任务成功、失败和服务重启后遗留运行记录处理。
  - 验证列表、详情、运行状态和历史接口响应字段。
- 前端：
  - 执行 `npm run build:prod`。
  - 验证策略列表、详情抽屉、运行轮询、成功结果、失败提示和历史记录展示。
  - 验证空策略目录、无行情数据、无基准数据和长时间运行状态下的界面行为。
- 接口验收：
  - 点击“运行策略”后不阻塞 HTTP 请求。
  - 页面可通过 `runId` 恢复并查看已持久化的历史结果。
  - 未填写基准代码时，基准和超额收益区域显示“不计算”。

## Assumptions

- 参考图中的收益指标、曲线和交易明细用于确定展示结构，不要求复制其平台专有功能。
- 回测结果需要持久化，因此会新增策略回测表及初始化 SQL。
- 默认基准为空；用户填写基准代码后才计算基准收益和超额收益。
- 后台任务采用当前 FastAPI 进程内执行，适用于单实例部署；后续如需多实例，可替换为现有任务调度或队列系统。
- 策略源码只读展示，不允许网页直接写回 `youw_test/strategies/` 文件。
