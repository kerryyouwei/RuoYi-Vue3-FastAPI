# 模拟交易分钟轮循自动买入设计

## 整体流程
1. 模拟交易页面继续使用现有“初始化账户”流程：选择策略、初始资金、标的池。
2. 新增后端分钟级任务：
   - 仅处理系统默认模拟盘账户。
   - 仅轮循 `stock_paper_universe` 中的有效标的。
   - 周一至周五触发，但只在 A 股交易窗口执行：09:30-11:30、13:00-15:00。
3. 每分钟批量获取实时行情：
   - 不使用 QUANTAXIS 统一入口，避免它依赖 MongoDB 配置和自动选 IP。
   - 复用 `real_data.py` 的底层 TDX 直连逻辑。
   - 主源 `shtdx.gtjas.com:7709`，备源 `sztdx.gtjas.com:7709`、`jstdx.gtjas.com:7709`。
4. 使用实时价作为“当前临时收盘价”：
   - 追加到历史日线最后一根 K 线。
   - 调用现有 `StockSignalService.compute_signal` 生成买入/卖出/持有信号。
5. 信号变化时立即撮合：
   - 买入：当前实时价成交，按总资产 / 标的池数量均分，100 股一手，校验资金。
   - 卖出：当前实时价成交，按可卖数量全仓卖出，卖出计印花税。
   - 持有：只更新最新价。
6. 每次撮合仍写入 `stock_paper_order`，同步更新 `stock_paper_account`、`stock_paper_position`、当日净值快照。
7. 同一标的当日只保留一条最新信号记录；相同信号不重复触发，避免每分钟重复下单。

## 关键调整
- 行情获取：
  - 在 `D:\BaiduNetdiskDownload\my_python\ruoyi_stock\RuoYi-Vue3-FastAPI\ruoyi-fastapi-backend\module_stock\service\stock_realtime_service.py` 增加可复用的实时行情函数。
  - 不直接 import `real_data.py`，因为该脚本当前有导入即执行的副作用。
  - 返回标准化字段：`code`、`price`、`volume`、`snapshot_time`。
- 模拟交易服务：
  - 在 `D:\BaiduNetdiskDownload\my_python\ruoyi_stock\RuoYi-Vue3-FastAPI\ruoyi-fastapi-backend\module_stock\service\stock_paper_service.py` 增加 `run_realtime_signal_and_execute()`。
  - 行情失败、价格无效、资金不足、无持仓可卖时写入跳过记录。
  - 保留现有收盘算信号和次日开盘撮合任务作为兜底。
- 定时任务：
  - 新增 `run_stock_paper_realtime` 任务函数。
  - 新增 idempotent SQL：`sql/stock_paper_realtime_job.sql`。
  - `sys_job` 使用每分钟 cron：`0 * * ? * MON-FRI`，时区 `Asia/Shanghai`，`max_instances=1`。
- 前端：
  - 模拟交易页增加“手动实时轮循”按钮。
  - 页面每 60 秒自动刷新账户、持仓、订单、净值。
  - 保留现有初始化、手动收盘算信号、手动开盘撮合能力。

## 测试计划
- 单元测试：
  - 行情字段标准化与多源回退。
  - 实时价追加到日线后能正确计算策略信号。
  - 信号变化触发一次买入；相同信号不重复触发。
  - 买入时资金不足、非 100 股整数倍、已有持仓的处理。
  - 卖出时 T+1 不可卖、无持仓、有持仓全卖的处理。
- 集成测试：
  - 手动调用实时轮循接口，验证账户、持仓、订单、净值更新。
  - 定时任务触发一次，验证日志、跳过原因和事务提交。
- 异常场景：
  - 行情源全部失败。
  - 返回价格为 0 / 负数 / 缺失。
  - 标的池为空或策略未配置。
  - 非交易时间和非交易日跳过。

## 假设与默认规则
- 当前版本只支持系统默认模拟盘账户，不做多账户。
- 只轮循模拟盘标的池，不轮循全市场。
- 只做模拟撮合，不接入真实券商下单。
- 信号口径采用“实时价替代当日收盘价”。
- A 股规则沿用现有实现：100 股一手、T+1、佣金、印花税。
