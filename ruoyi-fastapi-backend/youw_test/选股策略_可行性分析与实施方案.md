# 多因子小市值选股策略：可行性分析与落地实施方案

> 分析日期：2026-09-28  
> 原始说明：`youw_test/选股策略.md`  
> 目标：判断策略是否具备研究、回测和实盘落地条件，并给出与当前 RuoYi-FastAPI / QUANTAXIS / Backtrader 项目相匹配的实施步骤。

---

## 1. 执行摘要

### 1.1 总体判断

该策略的**研究方向可行**，但原始说明目前只够描述思路，**不具备直接回测或实盘条件**。

建议把它定位为：

- 一个以小市值暴露为底层风格、叠加质量、成长、动量和交易活跃度因子的周频横截面选股模型；
- 先复现原始版本作为基线，再通过标准化、分散持仓、流动性约束和严格的时点数据回测形成可实盘版本；
- 在完整样本外回测和至少 20～60 个交易日模拟盘通过前，不进入真实资金交易。

### 1.2 可行性评级

| 维度 | 评级 | 结论 |
|---|---:|---|
| 策略逻辑 | 3.5/5 | 多因子 + 小市值在逻辑上成立，但原始组合实际可能主要赚取小市值和流动性风险溢价 |
| 因子定义完整性 | 1.5/5 | ARBR、SGAI、Price1Y、VOL120、DAVOL20 等缺少精确定义、单位、方向和原始权重 |
| 数据可获得性 | 3/5 | 行情容易获取；精确复现供应商因子、历史 ST 状态、财务公告时点数据较难 |
| 当前系统适配度 | 2/5 | 已有行情和 Backtrader 框架，但缺少横截面因子库、财务数据、动态股票池和真实成交约束 |
| 回测可信度 | 1.5/5 | 若直接按说明实现，极易产生未来函数、幸存者偏差和不现实成交 |
| 实盘可执行性 | 2/5 | 单票、小市值、开盘调仓、涨跌停交易均会带来明显容量和成交风险 |

**最终结论：可以做，但必须先补齐因子定义和 Point-in-Time 数据。不能把原说明中的历史表现或“得分大于 0”直接视为有效信号。**

## 2. 当前策略逻辑复盘

原策略流程可以归纳为：

1. 从全 A 股构建初始股票池；
2. 排除上市不足 375 天、科创板、北交所、ST 股票；
3. 分别用三组因子做线性加权；
4. 每组取前 10%；
5. 在入选股票中优先选择流通市值较小且 EPS 大于 0 的股票；
6. 过滤停牌、涨停和跌停股票；
7. 每周一调仓，默认只持有 1 只股票；
8. 对昨日涨停持仓进行盘中开板监控；
9. 4 月 5 日至 4 月 30 日强制空仓。

三组因子覆盖：

- 组合 1：情绪、盈利质量、利润率、每股留存收益；
- 组合 2：一年价格动量、成本费用利润率、长期成交活跃度；
- 组合 3：资产负债率、销售成本率、短期成交活跃度、股价、营收增长。

从收益来源看，该策略并不是纯粹的“多因子模型”，更可能是：

> **小市值因子为主，盈利过滤和流动性/情绪因子为辅，再叠加单票集中持仓带来的高波动。**

因此，验证时必须将“小市值贡献”和“其他因子贡献”拆开，不能只看总收益。

## 3. 主要可行性问题与风险

## 3.1 因子定义不完整，是当前第一阻塞项

原始说明缺少以下关键信息：

- 每个因子的精确数学定义；
- 计算窗口和是否使用复权价格；
- 财务指标使用单季度、累计值、最近一期还是 TTM；
- 缺失值处理；
- 极值处理；
- 横截面标准化方式；
- 行业、市值中性化方式；
- 每组因子的原始权重；
- 权重符号的经济含义；
- `total_score > 0` 的分数基准。

若不同因子直接用原始值相乘再相加，量纲大的因子会主导结果。例如股价、资产负债率、营收增长率和换手率不在同一尺度上。此时“得分大于 0”没有稳定统计含义。

**必须执行：**

1. 找到原始策略代码或原始因子供应商文档；
2. 冻结因子版本，例如 `factor_spec_v1`；
3. 每个因子记录公式、数据字段、窗口、方向、发布日期滞后和缺失值规则；
4. 若无法取得精确定义，则按自定义公式重新命名，不能继续声称精确复现原策略。

## 3.2 SGAI、VOL120、DAVOL20 等可能是供应商专有因子

这些名称很可能来自特定量化平台的因子库。相同名称在不同数据源中未必含义一致。

建议分成两条路线：

### 路线 A：精确复现

使用原策略对应平台的数据和因子接口，保存每日因子快照。优点是定义一致，缺点是有授权、配额和供应商依赖。

### 路线 B：自主可维护版本

用原始行情和财务报表自己计算可解释因子，并重新做权重训练和样本外验证。优点是可控，缺点是结果不能与原策略直接等同。

推荐顺序：先用路线 A 验证原策略是否真的有效；确认有效后，再做路线 B 的可替代实现。

## 3.3 小市值排序可能吞噬多因子贡献

每组先取前 10%，之后再按流通市值升序选择，最终又只持有一只股票。这个流程非常容易退化成“小市值股票中挑一只”。

需要做以下消融实验：

| 实验 | 目的 |
|---|---|
| 仅小市值 + EPS>0 | 测量小市值基线收益 |
| 多因子、不按市值二次排序 | 测量因子独立贡献 |
| 多因子 + 市值中性化 | 判断因子是否脱离小市值仍有效 |
| 原策略全部规则 | 得到复现基线 |
| 去掉单票持仓，改为 10～20 只 | 测量集中度贡献 |

如果“仅小市值”与完整策略表现接近，应将策略重新定义为小市值增强策略，而非多因子 Alpha 策略。

## 3.4 单只持仓不可取

`g.stock_num=1` 会带来：

- 极高的公司特有风险；
- 财务造假、停牌、退市、黑天鹅风险无法分散；
- 收益曲线高度依赖少数股票；
- 回测结果对排序细节和数据误差极其敏感；
- 小资金也可能因一手 100 股和高价股而无法按目标权重成交。

建议研究版至少使用 10 只股票；资金较小、考虑一手约束时，也不应少于 5 只。最终数量应由资金规模、价格分布、手续费和流动性共同决定，而不是固定为 1。

## 3.5 周一 9:30 调仓容易引入时点问题

必须明确：

- 周一选股只能使用周一开盘前已经公开的数据；
- 日线、财务、ST 状态、流通股本和因子值都应截止到上一完整交易日；
- 财务数据必须按公告日期生效，不能按报告期结束日期生效；
- 回测中周一信号不能按周一收盘价成交；
- 若使用 9:30 指令，合理模拟应为开盘价加滑点、9:35 后成交，或使用开盘后 VWAP。

推荐生产流程改为：

- 上一交易日收盘后计算候选和目标权重；
- 交易日 9:20～9:25 再根据停牌、涨跌停和最新状态生成订单；
- 9:35 后分批执行，避免把集合竞价的理论价格当作必然成交价格。

## 3.6 零滑点假设不现实

小市值股票通常具有更高冲击成本，尤其在开盘、涨跌停附近和调仓拥挤时。

回测至少输出三档成本压力测试：

| 场景 | 佣金 | 印花税 | 单边滑点/冲击 |
|---|---|---|---|
| 乐观 | 账户实际费率 | 按回测期间当时规则 | 5bp |
| 基准 | 账户实际费率 + 最低佣金 | 按当时规则 | 10bp |
| 压力 | 账户实际费率 + 最低佣金 | 按当时规则 | 20～50bp，按流动性分层 |

交易税费必须做成按日期可配置规则，不能把一个固定费率覆盖整个历史区间。

## 3.7 涨跌停和停牌处理需要订单级模拟

“过滤涨跌停”只解决选股时的状态，不代表订单一定能成交。必须处理：

- 一字涨停无法买入；
- 一字跌停无法卖出；
- 停牌期间无法调整；
- 开板后成交价不等于涨停价；
- 卖出后资金何时可用；
- A 股 T+1：当日买入不能当日卖出；
- 除权除息导致的前收盘价和涨跌停价变化；
- 不同板块、ST 状态、上市初期的涨跌幅制度差异。

## 3.8 4 月强制空仓规则缺少可解释依据

4 月 5 日至 4 月 30 日清仓可能是在特定历史样本中拟合出来的规则。它可能规避年报风险，也可能只是数据挖掘。

必须做：

- 有/无 4 月空仓的对比；
- 将空仓窗口前后平移 5、10 个交易日的敏感性测试；
- 在不同年份和不同市场风格下分别统计；
- 观察它是否只是减少市场 Beta，而不是提高选股 Alpha。

没有稳定样本外证据时，不建议保留固定日历空仓。可改为基于财务风险、市场波动和流动性的动态降仓规则。

## 4. 当前项目的数据与引擎差距

结合当前代码，项目已经具备：

- `module_stock/service/stock_list_service.py`：通过 Baostock/QUANTAXIS 获取股票列表并写入 MongoDB；
- `module_stock/service/stock_day_service.py`：获取和查询股票日线 OHLCV、成交额；
- `module_stock/service/stock_realtime_service.py`：采集实时快照并计算简单均线信号；
- `module_stock/service/stock_strategy_service.py`：通过 Backtrader 执行策略、记录收益曲线、交易和基准表现；
- `youw_test/strategies/`：策略插件目录。

但本策略尚缺：

1. 全市场历史股票池和退市股票；
2. 历史 ST、停牌、板块和上市状态区间；
3. 前复权/后复权因子和不复权价格并存；
4. 每日流通股本、流通市值和换手率；
5. 三大财务报表、财务指标和公告日期；
6. 原始因子或自主因子计算模块；
7. 每个交易日的横截面因子快照；
8. 动态股票池和多股票组合回测；
9. 涨跌停、停牌、T+1、最小交易单位、成交量约束；
10. 滑点和市场冲击模型；
11. 按历史日期变化的税费模型；
12. 因子 IC、分组收益、换手率和归因报告。

当前回测服务主要以一个主代码和静态 `UNIVERSE` 加载数据。全 A 股周频横截面选股若把数千只股票全部作为 Backtrader Feed 加载，会占用大量内存并显著拖慢。建议在 Backtrader 之前增加“按日期生成目标组合”的向量化选股层，Backtrader 只负责订单和组合执行。

## 5. 数据准备清单

## 5.1 必需数据

### A. 证券主数据 `security_master`

| 字段 | 说明 |
|---|---|
| code | 统一证券代码 |
| exchange | 上交所、深交所、北交所 |
| board | 主板、创业板、科创板、北交所 |
| name | 当前名称 |
| list_date | 上市日期 |
| delist_date | 退市日期，未退市为空 |
| security_type | 股票、ETF、指数等 |
| status | 上市、暂停上市、退市 |

要求保留退市股票，避免幸存者偏差。

### B. 交易日历 `trade_calendar`

字段至少包括：交易所、日期、是否交易日、前一交易日、下一交易日。

### C. 日线行情 `daily_quote`

| 字段 | 用途 |
|---|---|
| trade_date, code | 主键 |
| open, high, low, close | ARBR、价格、成交模拟 |
| pre_close | 涨跌幅、涨跌停判断 |
| volume, amount | 流动性、成交约束 |
| pct_change | 数据校验 |
| paused | 停牌过滤 |
| upper_limit, lower_limit | 涨跌停判断 |
| adj_factor | 复权计算 |

必须同时保留：

- 不复权价：用于真实成交、涨跌停和价格因子；
- 前复权或收益率序列：用于动量、波动率和长期收益。

### D. 每日估值与股本 `daily_basic`

至少包括：

- 总股本、流通股本、自由流通股本；
- 总市值、流通市值；
- 换手率、自由流通换手率；
- PE、PB、PS（后续归因和扩展使用）。

### E. 财务报表与公告日期

需要利润表、资产负债表、现金流量表或已标准化财务指标，至少包含：

- 营业收入；
- 营业成本/销售成本；
- 净利润；
- 利润总额；
- 成本费用；
- 总资产；
- 总负债；
- 未分配利润；
- 基本/稀释 EPS；
- 营收同比增长率；
- 报告期、公告日期、实际更新时间、报告类型、是否更正。

最重要的时点规则：某份财务数据只能从其真实公告日之后的下一个可交易时点开始使用。对财务更正，应保留版本，回测只能使用当时已公开版本。

### F. 状态区间 `security_status_history`

至少记录：

- ST、*ST、退市整理状态的开始和结束日期；
- 停牌区间；
- 名称变更；
- 板块变更；
- 上市初期特殊涨跌幅状态。

### G. 指数与基准

至少准备：

- 中证 500：主基准；
- 中证 1000：检验小市值风格；
- 沪深 300：大盘风格对照；
- 全市场等权组合：判断是否只是市场普涨。

## 5.2 因子定义表

在开始编码前创建 `factor_definition`，每个因子必须冻结以下内容：

| 字段 | 示例 |
|---|---|
| factor_name | price_1y |
| version | v1 |
| formula | `close_adj(t-1)/close_adj(t-253)-1` |
| source_fields | daily_quote.close, adj_factor |
| lookback | 252 个有效交易日 |
| lag | 至少滞后 1 个交易日 |
| direction | 正向或负向 |
| winsorization | 横截面 1%/99% 或 MAD |
| standardization | 横截面 z-score 或 rank z-score |
| missing_policy | 丢弃、行业中位数填充或指定值 |
| availability_rule | 数据何时可见 |

建议初版自研因子定义如下，但必须与原供应商定义区分命名：

| 原名称 | 自研候选定义 | 风险/备注 |
|---|---|---|
| ARBR | 26 日 AR、BR，或二者差值/比值 | 必须确认原因子究竟是 AR、BR、AR-BR 还是组合标准分 |
| SGAI | 暂不猜测 | 找不到官方定义前禁止用名称相同的自造指标替代 |
| 净利润/营收 | 归母净利润 TTM / 营业收入 TTM | 使用公告日 Point-in-Time 数据 |
| 每股未分配利润 | 未分配利润 / 当期总股本 | 股本也要按当时可见值 |
| Price1Y | 约 252 交易日复权收益率 | 可增加跳过最近 20 日的 12-1 动量版本做对照 |
| 成本费用利润率 | 利润总额 TTM / 成本费用 TTM | 需统一“成本费用”口径 |
| VOL120 | 120 日换手率均值或供应商定义 | 名称可能不是成交量本身 |
| 资产负债率 | 总负债 / 总资产 | 金融行业口径特殊，宜剔除或单独标准化 |
| 销售成本率 | 营业成本 TTM / 营业收入 TTM | 越低是否越好需按行业处理 |
| DAVOL20 | 短期换手率相对长期换手率的差/比 | 必须确认供应商公式 |
| 不复权价格 | 上一交易日收盘价 | 原始值容易形成低价股暴露 |
| 营收增长率 | 最近可见的营收同比增长率 | 单季度和累计同比不能混用 |

## 5.3 数据源建议

### 推荐组合

- 行情和基础列表：可继续沿用 QUANTAXIS + Baostock，但需补齐复权、涨跌停、历史状态和退市数据；
- 财务和每日基本指标：选择有稳定历史接口、公告日期和更正版本的数据源；
- 精确复现原平台因子：优先使用原平台因子接口；
- 研究存储：Parquet 按 `trade_date` 分区，使用 Pandas/Polars/DuckDB 做横截面计算；
- 运行记录和配置：继续使用项目现有 SQL 数据库；
- 实时状态和任务缓存：可继续使用 Redis/MongoDB。

不建议仅依赖网页抓取型免费接口作为实盘主数据源，因为字段和接口可能变化，历史状态数据也常不完整。

## 5.4 数据量估算

以约 5,000 只股票、10 年、每年约 240 个交易日估算：

- 日线约 1,200 万行；
- 每日基本指标约 1,200 万行；
- 宽表因子快照约 1,200 万行；
- 财务报告约数十万行。

使用按日期分区的 Parquet 或列式数据库后，单机研究可行。若全部按 Python 对象或数千个 Backtrader Feed 常驻内存，效率会较差。

## 6. 推荐的策略 V1 规则

V1 分为“原始复现版”和“可实盘增强版”，两者同时保留，不能边复现边修改。

## 6.1 原始复现版 `baseline_v1`

严格按原逻辑：

1. 截止 T-1 日构建全市场股票池；
2. 上市满 375 天；
3. 排除科创板、北交所、ST；
4. 按三组原始因子和权重分别评分；
5. 每组取前 10%；
6. 要求 EPS>0；
7. 每组按流通市值升序；
8. 合并去重；
9. 按原始持仓数和调仓规则执行；
10. 保留 4 月空仓和涨停开板规则。

该版本仅用于验证原说明，不直接实盘。

## 6.2 可实盘增强版 `production_candidate_v1`

### 股票池

- 上市满 375 个自然日；
- 排除 ST、*ST、退市整理、暂停上市；
- 排除上市初期特殊交易阶段；
- 科创板、北交所默认排除；创业板是否纳入做独立配置；
- 最近 60 个交易日有效行情不少于 55 日；
- 最近 20 日成交额中位数达到设定门槛；
- 股价过低、长期停牌、无法取得完整财务数据的股票剔除。

### 因子预处理

每个调仓日按横截面执行：

1. 使用 T-1 日可见数据；
2. 缺失比例超过阈值的因子暂停使用并报警；
3. 对极值做 MAD 或 1%/99% 缩尾；
4. 对偏态指标可先做 `log1p`；
5. 做 rank z-score 或标准 z-score；
6. 对资产负债率、销售成本率等强行业因子做行业内标准化；
7. 可额外做市值中性化，用于验证非小市值 Alpha；
8. 因子方向统一为“值越大预期收益越高”。

### 组合打分

推荐两种方式同时回测：

- **原组合加权**：每组标准化后线性加权，再对三组分数平均；
- **排名集成**：每个组合形成百分位排名，最终取三组平均排名。

排名集成对量纲和极值更稳健，适合作为生产候选。

### 选股和持仓

- 目标持仓：10～20 只；
- 等权为基准，逆波动权重作为对照；
- 单票目标权重不高于 10%；
- 单行业权重不高于 25%；
- 新买入进入前 N 名；
- 已持仓只有跌出 1.5N 或 2N 后才卖出，降低换手；
- 若可选股票不足，不强行满仓；
- 组合现金作为正常状态保留。

### 流动性与容量

- 单笔交易金额不超过最近 20 日成交额中位数的 1%～5%；
- 压力测试中按参与率增加冲击成本；
- 一字板不假定成交；
- 高开或低开超过阈值时可延迟到 9:35～10:00 执行；
- 订单拆分和未成交订单必须记录。

### 调仓

- 信号：上一完整交易日收盘后生成；
- 正式调仓：每周第一个交易日；
- 成交：下一可交易时点；
- 因节假日导致周一休市时，顺延到该周首个交易日；
- 先卖后买，但跌停无法卖出时要相应压缩新买入规模。

### 风控

优先使用组合层风控，不建议一开始加入大量个股止损参数：

- 最大单票和单行业权重；
- 流动性门槛；
- 财务数据过期/异常报警；
- 组合回撤分级降仓规则作为独立实验；
- 市场极端波动时暂停新增仓位；
- 数据不完整时 fail closed，即不生成新订单，而不是用旧值静默交易；
- 涨停打开卖出规则单独做消融，不默认认定有效。

## 7. 回测设计

## 7.1 时点与防偏差要求

回测必须同时满足：

- 使用历史时点可见的股票列表，包含后来退市股票；
- 使用历史 ST 状态，而不是当前 ST 状态；
- 财务数据按公告时间生效；
- 复权只用于收益计算，不用于虚构成交价格；
- 调仓信号与成交至少错开到下一可交易时点；
- 不允许用当天收盘后数据在当天开盘成交；
- 停牌、涨跌停、T+1 和一手 100 股约束进入订单模拟；
- 未成交订单不得自动按理想价格补成交。

## 7.2 样本划分

建议至少覆盖一个完整牛熊周期，并采用滚动样本外验证：

- 训练期：用于确定因子方向和初始权重；
- 验证期：用于比较版本和选择少量参数；
- 测试期：参数冻结后一次性评估；
- 最终报告更新到 2026-09-28 之前的最新完整交易日。

推荐 Walk-Forward：

- 用过去 3～5 年数据训练或校准；
- 用下一年做样本外测试；
- 每年滚动一次；
- 不允许看完测试结果后继续反复调整同一测试区间。

## 7.3 必须输出的指标

### 组合指标

- 累计收益、年化收益；
- 相对中证 500 的超额收益；
- 相对中证 1000 和全市场等权的超额收益；
- 年化波动率、Sharpe、Sortino；
- 最大回撤、回撤持续时间、Calmar；
- 月胜率、年胜率；
- 换手率、持仓天数、成交失败率；
- 交易成本占毛收益比例；
- 资金容量估算。

### 因子指标

- 日/周 RankIC 均值和 ICIR；
- 因子分组收益及单调性；
- 因子覆盖率和缺失率；
- 因子间相关性；
- 因子收益在不同年份、行业和市值组的稳定性；
- 行业、市值、Beta、波动率暴露；
- 单只股票和单个年份的利润贡献集中度。

## 7.4 消融和敏感性测试矩阵

至少完成以下版本：

1. 原始全规则；
2. 仅小市值 + EPS>0；
3. 去掉小市值二次排序；
4. 去掉每个因子，逐一观察贡献；
5. 三组因子分别独立运行；
6. 原始值加权 vs 标准化加权 vs 排名集成；
7. 持仓 1、5、10、20、30 只；
8. 每周、双周、每月调仓；
9. 有/无 4 月空仓；
10. 有/无涨停开板卖出；
11. 有/无行业中性化；
12. 有/无市值中性化；
13. 5bp、10bp、20bp、50bp 滑点；
14. 不同流动性门槛；
15. 参数上下浮动 10%～20%。

## 7.5 上线门槛

建议满足以下门槛后才进入模拟盘：

- 样本外相对基准有正超额，而不是只在训练期有效；
- 扣除基准成本和压力成本后仍为正；
- 最大回撤和回撤持续时间在账户可承受范围内；
- 参数轻微变化不会使结果从显著盈利变为显著亏损；
- 收益不依赖单一年份、单只股票或少数涨停成交假设；
- 因子分组收益具备基本单调性；
- 相比“仅小市值”基线有稳定增益；
- 模拟盘订单、价格和回测假设基本一致。

示例研究门槛可设为：样本外年化超额收益大于 3%、信息比率大于 0.5、压力成本下超额仍为正、单年利润贡献不超过总利润的 50%。这些是项目验收线，不是收益承诺，可根据账户风险重新设定。

## 9. 分阶段执行计划

## 阶段 0：定义冻结，1～2 个工作日

交付物：

- 原始策略代码或来源确认；
- 12 个因子的精确定义；
- 三组权重；
- 因子方向、缺失值和标准化规则；
- 股票池、调仓时点和成交规则；
- `factor_spec_v1.yaml`。

验收：任何开发人员按文档可得到相同的单日因子值和选股结果。

## 阶段 1：数据底座，3～7 个工作日

交付物：

- 股票主数据和交易日历；
- 日线、复权、涨跌停、每日基本指标；
- 财务原始数据和公告日期；
- 历史 ST/停牌/退市状态；
- 数据质量报告。

验收：随机抽取 20 只股票、10 个日期，与数据源核对；退市股票和历史 ST 股票可被正确查询。

## 阶段 2：因子引擎，3～5 个工作日

交付物：

- 12 个因子计算器；
- 横截面预处理；
- 单日因子快照；
- IC、分组收益和相关性分析；
- 因子单元测试。

验收：无未来数据；同一数据版本重复计算结果一致；缺失和异常数据有明确日志。

## 阶段 3：组合回测，4～7 个工作日

交付物：

- 动态股票池；
- 多股票目标权重；
- A 股成交约束；
- 税费、滑点和容量模型；
- 基线、增强版和消融实验报告。

验收：不存在同日未来成交；一字板和停牌无法成交；现金和持仓可逐笔对账。

## 阶段 4：参数冻结和样本外测试，2～4 个工作日

交付物：

- 冻结参数版本；
- Walk-Forward 报告；
- 成本压力测试；
- 风格暴露与收益归因；
- 上线/否决结论。

验收：测试期未被用于再次调参；完整记录每个版本和结果。

## 阶段 5：模拟盘，至少 20～60 个交易日

检查：

- 信号生成是否准时；
- 数据缺失时是否停止错误交易；
- 理论订单与真实可成交价格偏差；
- 涨跌停、停牌、最小佣金和一手约束；
- 回测滑点假设是否覆盖模拟盘滑点；
- 组合偏离和调仓失败后的恢复机制。

## 阶段 6：小资金灰度实盘

前提：模拟盘通过，账户交易规则已核实，并设置人工复核和一键停止。

上线顺序：

1. 仅生成信号，不自动下单；
2. 人工确认后下单；
3. 小资金、低参与率；
4. 对账稳定后再考虑半自动或自动化；
5. 任何数据版本变化均重新跑回归测试。

## 11. 建议的第一轮最小可行实验

为了尽快判断是否值得继续投入，第一轮不必直接搭完整实盘系统，可以按以下顺序完成：

1. 选取至少 5～8 年历史数据；
2. 暂时剔除无法确认定义的 SGAI，并对其余因子做可解释自研实现；
3. 全部因子按日横截面 rank z-score；
4. 使用 T-1 信号、下一交易日开盘加 10bp 滑点成交；
5. 持仓 10 只，等权，每周调仓；
6. 加入上市 375 天、历史 ST、停牌、涨跌停、EPS>0 和流动性过滤；
7. 对比：仅小市值、多因子无市值排序、多因子加市值排序；
8. 输出样本外收益、最大回撤、换手、成本、RankIC 和市值暴露；
9. 若多因子版本不能稳定战胜仅小市值版本，则停止复制原权重，转为重新研究因子；
10. 若压力成本下仍有稳定超额，再投入动态组合执行和模拟盘。

这个最小实验的目的不是证明策略赚钱，而是用最低成本回答两个问题：

- 多因子是否真的提供了小市值之外的增益？
- 增益在真实成本和时点约束下是否仍存在？

## 12. 最终建议

1. **先找原代码和权重。** 当前说明缺少最关键的可复现信息。
2. **不要直接使用原始值线性相加。** 先做横截面缩尾和标准化。
3. **不要单票实盘。** 至少做 5/10/20 只的分散化对照。
4. **不要只与中证 500 比。** 同时与中证 1000、全市场等权和纯小市值基线比较。
5. **把财务公告时点作为硬要求。** 否则回测很可能存在未来函数。
6. **将小市值、流动性和成交限制纳入回测。** 小盘策略最容易因理想成交而虚高。
7. **4 月空仓和涨停开板卖出必须做消融。** 没有样本外证据不要保留。
8. **当前系统应增加向量化横截面选股层。** 不建议把全 A 股直接作为数千个 Backtrader Feed 计算因子。
9. **先完成最小可行实验，再决定是否建设完整实盘链路。**

> 本方案用于量化研究和软件实施，不构成收益承诺或个股投资建议。
